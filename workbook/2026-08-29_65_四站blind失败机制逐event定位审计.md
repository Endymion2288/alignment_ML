## 预注册问题与判定框架

**主问题**：`draw_00` 从 nominal 掉 0.117 的 complete-track efficiency，
损失链在哪一层？

预注册损失链分解（与生产代码一一对应）：

```text
candidate graph（物理 ACTS 边存在性）
  → edge raw probability / ranking（冻结 V2）
  → calibrated probability（identity Platt）
  → 0.001 station-pair threshold
  → complete truth-route utility U_truth = Σ log-odds + 4·(-1)
  → fragment / dustbin competitor utility（production _route_hypotheses，U>0）
  → set-packing winner（unit-capacity，含 tie-break）
  → complete-track efficiency
```

失败类别（预注册定义，判定用 matched event 证据，不预设答案）：

- **A. candidate 缺失**：某 adjacent truth edge 不在物理 candidate graph。
  条目 64 已基本排除（recall=1.0），本审计仍逐 event 复核。
- **B. 单边 score/ranking 失败**：某 truth edge 的 calibrated 概率
  在其 source（或 pair 内）非 rank-1，且低于 competitor 边。
- **C. absolute score-scale / operating-layer 失败**：truth edge 仍全部
  rank-1，但绝对概率下移导致 `U_truth≤0` 或低于阈值/竞争 Utility。
- **D. route utility aggregation / set-packing interaction**：每条 truth
  edge 单独看都合理（rank-1、过阈），但 Σ log-odds 加 4×(−1) 的 utility
  被 fragment/dustbin 击败；或 packing 因 endpoint 冲突选中别的组合。
- **E. absolute-coordinate-sensitive representation 缺 global context**：
  以上都不是，且 matched twin 对照显示失败与 station 状态绝对量的
  多站相对几何组合相关（例如同一 origin route 只在某组相对参数下失败，
  且失败与 S3 participation 强绑定，超出单边/尺度/聚合可解释范围）。

### 3. 核心问题解答：`draw_00` 掉 0.117 效率的根因

**定量构成**：
- `reference` 未选中 route：14 (C) + 18 (D) = 32 条 (32 / 480 = 6.67%)
- `draw_00` 未选中 route：49 (C) + 39 (D) = 88 条 (88 / 480 = 18.33%)
- 净损失：$88 - 32 = 56$ 条 route ($56 / 480 = 0.11667 \approx 0.117$)
- **类别 C ($U_{\text{truth}} \le 0$) 贡献**：$+35$ 条 ($35 / 56 = \mathbf{62.5\%}$)
- **类别 D (Packing Competition) 贡献**：$+21$ 条 ($21 / 56 = \mathbf{37.5\%}$)
- **类别 A (Candidate Missing) 与 B (Edge Thresholding)**：$0$ 条 ($\mathbf{0.0\%}$)

**物理退化机制分析**：
1. **站对 Logit 与概率退化**：
   - 0→1 站对：mean logit $2.114 \to 2.038$，mean prob $0.885 \to 0.875$（微小变化）
   - 1→2 站对：mean logit $1.336 \to 1.301$，mean prob $0.788 \to 0.780$（微小变化）
   - 2→3 站对：mean logit $2.180 \to 1.828$（明显下降），mean prob $0.893 \to 0.845$；$P_{2\to3} < 0.5$ 的低分边比例由 0.8% 激增至 4.2%（5.25 倍）
2. **$U_{\text{truth}}$ 与 Margin 压缩**：
   - 全 route utility $U_{\text{truth}} = P_{0\to1} + P_{1\to2} + P_{2\to3} - 3.0$ 中位数从 $1.901$ 跌落至 $1.566$
   - $U_{\text{truth}} \le 0$ 的非正效用比例从 2.9% (14条) 扩大到 10.2% (49条)，直接导致 solver 因 dustbin penalty 放弃该 route（哪怕没有任何竞争者）
   - Production margin 中位数从 $1.181$ 降至 $0.927$
3. **S3 站参与度**：
   - `draw_00` 未被选中的 88 条 route 中，45 条（51.1%）存在直接 S3 边分值崩溃或 S3 竞争 fragment 冲突。
4. **Gauge Twin 对齐（`draw_00` vs `draw_00_plus_common`）**：
   - 同源对齐的 130 条 track 中，`reference` 选中 121 条，`draw_00` 选中 104 条，`draw_00_plus_common` 选中 106 条。
   - `draw_00` 丢失的 17 条 nominal 命中 route 中，有 7 条（41.2%）在加上 common 模式后被 twin 恢复（说明部分损失来自坐标系绝对方向与特征投影的非完全等变相互作用）。

### 4. 形式化归因判定（Decision Verdict）

- **A (Candidate Builder)**：排除（100% recall，0 损失）。
- **B (Edge Ranking / Single-edge Thresholding)**：排除（100% 边通过 0.001 阈值，0 单边截断）。
- **C (Absolute Score-Scale / Route Utility Threshold)**：**主因，占 62.5%**。大错位（尤其是 S3 相关的多轴错位）导致 2→3 边概率系统性下移，3 边概率和不足以抵消 unmatched penalty，导致 $U_{\text{truth}} \le 0$ 无法产出。
- **D (Route Utility Aggregation & Set Packing Competition)**：**次因，占 37.5%**。在 $U_{\text{truth}}$ 被压低至 $(0, 1)$ 区间时，2 站/3 站 fragment 竞争对手（如 0-1-2 或 1-2-3）具有更高或相近 utility，导致 set packing 倾向于选择局部高分 fragment 而打碎完整 4 站 route。
- **实现 Bug 嫌疑**：**已排除**。代码、阈值、数学定义完全符合合同规范。
