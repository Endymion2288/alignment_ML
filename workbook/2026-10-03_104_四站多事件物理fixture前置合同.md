仅处理 WB103 §2 的六个 source/ordinal/header/row identity：WB92 fixture indices `1,4,8,12,16,20`，分别为 ordinals `2141,2310,2327,2268,2305,2287`。输入仍属于已见 development；raw xAOD SHA-256 必须在 worker 开始前逐文件计算并冻结，任何 stat/byte/ROOT metadata 改变均为 identity failure。

使用的基础证据必须来自以下已存在且通过的链：

- WB91 v7 `array_inputs.json`、`selection.json`、每个 `physical/<index>/repair.jsonl` 与 `validation.json`；
- WB92 v3 `fixtures.json`、`freeze.json`、官方 common-seed source/build，及已通过的 index 0 pilot；

六个 event 的 source+ordinal+actual `(run,event)` 是唯一键。run/event 跨 source 重复时不得合并；任何重复或缺失均为 UNKNOWN。

## 2. 只允许的前置链

每个选定 event 必须按同一官方条件链独立生成：

`WB91 repaired state (state_index=0)` → `WB92 common-seed ACTS target/sensor fixture` → `WB93 transport/reference fixture` → `WB94 field-boundary fixture` → `WB95 double/float reference ladder` → `WB96 disabled/tolerance baseline` → `WB101 direction-acceptance baseline guards`。

各层必须使用 `scripts/setup_environment.sh calypso` 和同一 LCG/Calypso release、FASERNU-04、OFLCOND-FASER-06、实际 `tracker_alignment.sqlite`、FASER field service、ACTS 32.0.2 及原有 `material=false/covariance=false` 语义。每层使用独占输出目录和独占 event fixture；不得覆盖对应历史 WB92–WB101 输出。

前置链可复用已冻结二进制和科学源，但仅在源 hash、official library hash、field map hash、geometry/global-tag、sqlite/POOL payload hash 全部相同的条件下复用。若某层只能通过改变 solver、frame、step policy、field backend 或 q/p 语义来运行，应停止并将该层记为 UNKNOWN。

## 3. 必须保存的 event-specific 产物

每个 event 最少保存并互相绑定：

1. source path、raw file SHA-256/size、ordinal、实际 EventInfo run/event、WB91 row/repair SHA；
2. WB92 `acts.json`、fixture、Athena log、target station frame、sensor list、seed/q/p 单位和 loaded library hashes；
3. WB93/WB94 reference/field-boundary states 及其 source/conditions identity；
4. WB95 `mesh_z_double`/`mesh_z_float` 三阶梯、node payload hash、reference qualification summary；
5. WB96 `wb96_fixed_start`、完整 disabled/tolerance acts、saved baseline states、trial/field accounting；
6. WB101 complete disabled baseline guards，覆盖四 cap、三 target、所有 25-point perturbation row 所需的结构字段；
7. 独立 manifest：每个文件 SHA-256、producer commit、branch=`4station`、environment、Condor worker/terminal receipt。

任何缺少 event-specific 目标 frame、fixed-start、baseline guard、reference node 或 library/field identity 的 event，不得进入 WB103。

## 4. 前置门与判决

每层先完成 identity/structure gate，再允许下一层。六个 event 必须全部满足：

- source/ordinal/header 与 WB103 表一致；
- event-specific target/sensor geometry 来自该 event 的实际 official chain；
- WB95 reference ladder 完整，且按历史 reference 规则给出 PASS/UNKNOWN，不把 WB102 pilot ladder 当替代；
- WB96/WB101 baseline 的完整矩阵、disabled structural guards 和 field/query accounting 均存在；
- 所有 payload、field map、official/isolated libraries 与冻结条件 hash 一致；
- negative controls（wrong source/header/frame/node/mesh/q/p unit/NaN）能被检测；
- scheduler 为 single-start 正常终止，worker error、missing output、silent fallback 都单独记录。

六个 event 全部通过才允许把 preflight 状态置为 `PASS_READY_FOR_WB103`。任何 identity/参考前置缺失为 `UNKNOWN`；前置执行代码或汇总崩溃为 infrastructure `FAIL`，必须保留原失败目录并在新独占目录恢复。该 preflight 通过本身不产生 Jacobian 科学结论。

## 5. 资源和执行边界

这是六个独立 event 的长批处理，优先 Condor；提交前检查当前 schedd/slot，必要时选择有空闲槽位的 schedd。worker 不读 sealed/held-out，不训练 ML，不提交 alignment solve，不写 WB102/WB103 输出，不自动 retry。每个 event 可独立重跑，但重跑必须新目录并绑定原失败 receipt。

本合同不规定或授权 WB103 的 `5056 calls/event` Jacobian 矩阵；只有六个 preflight manifest 完整封存后，才可评审 WB103 实现是否满足其科学合同。
