# V3 结构化全局指派与扩展物理语料

## 本轮边界

- 不加深 Transformer；V3 固定使用 V1/V2 的 `d_model=128`、4 block、8 head、FFN `128 -> 256 -> 128`。
- 不生成新 test bank，不打开 V1 封存 test source 或 artifact。
- V3 的 model、loss、calibration 和 threshold 选择只允许 train/validation。
- 物理链不变：`SCT_ClusterContainer -> SegmentFitRefit -> SegmentsRefit -> NtupleDumper -> FaserActsExtrapolationTool(mode 0)`。
- 不使用 local segment `q/p`，不使用 residual-level 或 coordinate-level surrogate。

## V3 结构化目标

新增 `training/structured_assignment.py`。训练不再使用 independent edge/route BCE，而是对每个 event 构造 truth-consistent complete route 的 maximum-cardinality unit-capacity assignment `Y`，再使用同一 exact unit-capacity solver 找到 loss-augmented 最强竞争 assignment：

```text
Y_hat = argmax_A [U_theta(A) + m Delta(A, Y)]
L = relu(U_theta(Y_hat) + m Delta(Y_hat, Y) - U_theta(Y))
```

complete-route utility 为三条 adjacent edge logit 之和加已有 route encoder 的 learned residual。mixed truth、fake endpoint、duplicate truth、endpoint conflict 和 hard negative 都作为明确竞争类别。truth/synthetic provenance 只作 label/audit，不进入 feature。

`baselines/route_assignment.py` 增加通用 `solve_unit_capacity_route_packing`；V3 的 training oracle 与既有 route inference 保持一致的 unit-capacity 约束。最终 inference backend 不变。

实现 `soft_unit_capacity_assignment_surrogate` 作为可微对照。完整 route 是四 endpoint hyperedge，不能把它误称为精确 matrix Sinkhorn；主 V3 config 的该项权重为 0。

新增：

- `configs/geometry_aware_transformer_v3.yaml`
- `configs/geometry_aware_transformer_v3_soft_assignment_control.yaml`
- `scripts/train_structured_assignment_v3.py`
- `scripts/evaluate_structured_assignment_v3.py`
- `tests/test_structured_assignment.py`

checkpoint 选择只按 validation structured hinge，再按 validation violation fraction；不以 calibration、threshold 或最终 route metrics 选择。固定 gate 是 nominal efficiency `>=0.70`、purity `>=0.95`、fake `<=0.05`，且 5/10 mm 必须胜过相同 expanded corpus 上重新训练的 MLP/V1/V2。

## V3 exact oracle 吞吐量

新增 `scripts/audit_structured_route_oracle.py`，只允许 `--split train` 或 `--split validation`，显式拒绝 test。它对真实已 materialize 的 physical candidate graph 统计 complete route 与 endpoint-conflict component，并用 deterministic positive utilities benchmark exact solver。训练 split 的 7,200 graph 平均有 116.77 complete route（median 108、p99 336、max 720），而 component 平均 117.16 route，说明一个 event 内多数 route 相互连通，单纯拆 component 无法显著减少求解工作。

因此将 generic exact unit-capacity packing 加入固定顺序 multipartite hyperedge 的 dynamic-programming fast path：只要完整 route 的 endpoint 在 tuple position 上形成分区，就按第一站 endpoint 分组、以其余站 endpoint occupancy bitmask 做精确 DP；mixed-length route、position 不可分或超过 200k state 的实例仍回退 SciPy MILP。这个变换不改变 candidate、可行域、utility 或 loss-augmented target。新增单元测试覆盖：DP 不调用 MILP、同 brute-force optimum 一致、generic non-partitioned fallback 仍按 component 精确求解。当前修正后的 64-event audit 平均 oracle 时间为 `4.6147 ms/event`（median `2.9921 ms/event`），相对于 generic MILP 的 `24.18 ms/event` 保持显著加速。
