# 2026-08-08：data0 与 MC22 复审

## 目的

响应对 `/eos/experiment/faser/data0` 和 2022 MC 的进一步检索。在不从 raw hit
重新做 tracking 的前提下，寻找同时满足 local tracklet、显式 station、covariance 和
MC truth 需求的输入，或确认可作为最小 smoke test 的替代样本。

## 已确认的 data0 内容

1. `data0/phys/2022_ift/r0022` 存在多 run 的已生成 PHYS 输出。
   `008090/Faser-Physics-008090-00000-00022-r0022-PHYS.root` 的 `nt` tree 有
   18,363 行；其中 18,116 行 `TrackSegments>0`。这证明该 PHYS 输出中有 local
   segments，但它仍是 legacy 格式，缺 station ID、covariance、hit 摘要和
   per-tracklet truth。
2. `data0/rec/2022/r0022/008090/Faser-Physics-008090-00000-r0022-xAOD.root`
   有 44,639-entry `CollectionTree`，持久化 key 包含 `SegmentFit`、`Segments`、
   `CKFTrackCollection*`、`SCT_ClusterContainer` 和 `SCT_SpacePointContainer`。
3. 使用当前 Calypso runtime 加 `--useIFT --export-tracklets --NoTrackFilt
   --no_stable --skip-ghostbusters`，保留默认 blinding，对此 xAOD 的前 10 与前 100
   event 都实际运行过。输出 ntuple 行数分别为 10 与 100，但 `SegmentFit`、`Segments`
   和 `Tracklet_*` 全为空。
4. 现有 PHYS 的首个 event ID 为 `767688`，而上述 re-export 的 event ID 为
   `1...100`。不能从 filename 推断二者是同一 event 序列；当前应将这对 xAOD/PHYS
   视为 provenance 未确认，不能当作 V1 real-data 输入。
5. 初版导出无条件运行 GhostBusters，会对已经持久化的 `Segments` key 出现 duplicate
   writer 警告。已向 `faser_ntuple_maker.py` 加入 opt-in
   `--skip-ghostbusters`。使用它后 warning 消失，但前 100 event 仍无 segment，故
   问题不是该重复 writer 单独造成的。

## MC22 结论

1. `data0/sim/mc22/particle_gun/100022/rec/s0012-r0019/`
   的 100 GeV electron xAOD 与此前导出的 `/eos/experiment/faser/sim/...` 文件是
   同一个 EOS inode。
2. 已验证的 10-event 导出给出 28 条 tracklet，station counts 为
   `1:10, 2:13, 3:5`；28/28 covariance 正定；truth PDG 为 17 条 `-11` 和 11 条
   `11`。它可用作三站电子 exporter/loader/chi2 smoke test。
3. 在 `data0/sim/mc22` 的重建 xAOD 路径中，未找到 `r0022` tag 或 filename 含
   `IFT` 的候选。不能据此否定整个 EOS 上存在其它 production，但不能把当前
   MC22 electron 样本扩展解释为 IFT+后三站。
4. `data0/sim/mc22/foresee/110052` 有 multi-lepton `Aee` PHYS 输出，但检查到的
   `rec` 目录为空。只有 legacy PHYS 时，不能补出 station/covariance/hit/truth
   association，不在本阶段通过 RDO 重建。

## 判断与下一步

- 继续把 MC22 electron 作为三站 smoke test，不作为 capture-range 的四站主要结果。
- 四站 schema/infrastructure 继续由已验证的 MC24 FASERnu muon control 完成。

  freeze-network 的 residual-only alignment 阶段。
